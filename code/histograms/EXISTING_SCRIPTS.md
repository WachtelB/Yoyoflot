# Поиск расхождений в данных

## Распределение пассажиров по числу перелётов

`count_passenger_flights.py` и `passenger_flight_counts.sql` объединяют
`boarding_data.PassengerDocument → TicketNumber` и `sirena.TravelDoc → e-Ticket`.
Для каждого документа считается количество **различных номеров билетов**.
Одинаковый билет одного документа в обеих таблицах считается один раз.
Документы, встречающиеся только в одном источнике, тоже включаются.

Пробелы в документах и билетах удаляются, регистр приводится к верхнему.
Номера остаются строками с сохранением ведущих нулей. Пустые значения,
`Not presented`, `N/A`, `None`, `NULL`, `-` считаются пропусками.
Неизвестные документы исключаются. Документ без известных номеров билетов
сохраняется с нулевым счётчиком: это ноль **известных билетов**, а не отсутствие
реальных перелётов. Один человек с разными документами будет в разных группах.
Билет с несколькими сегментами всё равно считается одним перелётом по заданному правилу.

```powershell
.\закройте приложение, которое держит файл базы
py code/histograms/count_passenger_flights.py
```

Результаты сохраняются через `pathlib.Path` в `results/passenger_flight_counts/`:

- `passengers.csv`: документ, число уникальных билетов и ФИО;
- `distribution.csv`: число перелётов и число документов с таким счётчиком;
- `histogram.png`: X — число перелётов, Y — число пассажиров (документов).
- `statistics.json`: Q1, Q3, среднее и границы доверительного интервала среднего.

Повторный запуск обновляет эти файлы. Основная база не изменяется.
Также открывается интерактивное окно Matplotlib: на панели есть масштабирование,
перемещение, возврат к исходному виду и сохранение изображения.
В начале скрипта `SHOW_WINDOW = True` включает окно; `False` оставляет только
сохранение CSV и PNG. База закрывается до открытия графика, а скрипт завершается
после закрытия окна.

`SELECTED_FLIGHT_COUNT = 16` задаёт, для какого **точного** числа перелётов
печатать ФИО в консоли. Например, 2 покажет имена документов с двумя билетами.
В консоли больше нет общей таблицы распределения и сообщений о путях к файлам.
Гистограмма и CSV по-прежнему содержат все группы, независимо от этой переменной.
Если в группе нет известных имён, консоль остаётся пустой.

ФИО берутся из трёх полей BoardingData и `sirena.PaxName`. Разные написания
имени одного документа перечисляются через ` / ` в одной строке.
Это варианты имени из источников, а не несколько отдельных пассажиров.

На гистограмме отмечены **Q1 (25-й процентиль)** и **Q3 (75-й процентиль)**,
среднее и его доверительный интервал. `ALPHA = 0.05` задаёт уровень значимости
5%, то есть доверительный уровень 95%. Квартили и интервал считаются по всем
документам с учётом частот, включая нулевые счётчики, независимо от
`SELECTED_FLIGHT_COUNT`. Для квартилей используется линейная интерполяция NumPy.

ДИ среднего: `mean ± z × s / sqrt(n)`, где `s` — выборочное стандартное
отклонение (`ddof=1`), `z ≈ 1.96` при `ALPHA = 0.05`.
Это нормальное приближение для большой выборки; оно предполагает независимые
наблюдения. Источники проекта не являются случайной выборкой всех пассажиров,
поэтому переносить такой интервал на всех авиапассажиров нельзя.
Он характеризует точность оценки среднего в этой модели, а не диапазон,
содержащий 95% пассажиров. Узкий интервал также показан на увеличенном фрагменте.
Для одного документа ДИ не рассчитывается, поскольку нельзя оценить дисперсию.

## Число рейсов в/из городов и аэропортов

Скрипт `count_flights_by_location.py` использует `flight_locations.sql`.
Считает **уникальные пары «номер рейса + дата» для каждого места и направления**,
а не пассажиров или количество исходных строк. Рейс с одинаковым номером
в разные дни учитывается отдельно. Повторы пассажиров и источников не увеличивают
счётчик в одном месте. Номер рейса приводится к верхнему регистру без пробелов,
место — к верхнему регистру без пробелов по краям, дата — к типу `DATE`.

| Источник | Город отправления | Город прибытия | Аэропорт отправления | Аэропорт прибытия |
| --- | --- | --- | --- | --- |
| boarding_data | — | Destination | — | — |
| boarding_passes | from_city | to_city | from_iata | to_iata |
| sirena | — | — | From | Dest |
| forum_flights | from_city | to_city | from_iata | to_iata |
| pointz_activities | — | — | origin | destination |
| skyteam_exchange | — | — | from_iata | to_iata |

Объединение сделано через `UNION ALL` и `DISTINCT`, чтобы избежать перемножения
пассажирских строк при JOIN. Отсутствующие поля города не восстанавливаются
по аэропорту. Используются шесть исходных таблиц; ранее объединённая таблица
boarding_data + boarding_passes дополнительно не включается.

Запуск из корня проекта:

```powershell
.\закройте приложение, которое держит файл базы
py code/histograms/count_flights_by_location.py
```

Результаты печатаются и сохраняются в `code/histograms/results/flights_by_location/`:
`city_departures.csv`, `city_arrivals.csv`, `airport_departures.csv`,
`airport_arrivals.csv`. При повторном запуске эти отчёты перезаписываются.
Основная база не изменяется, промежуточная таблица временная.

### Диаграммы

После подсчёта автоматически строятся четыре горизонтальные столбчатые диаграммы:
прилёты и вылеты по городам и аэропортам. Изображения PNG находятся в подпапке
`results/flights_by_location/charts/`. Для коротких списков дополнительно создаётся
`overview.png` — все четыре диаграммы на одном листе. Самые редкие места сверху,
числа подписаны возле столбцов. Используются именно места из текущих CSV,
то есть выбранные настройкой `BOTTOM_N` при последнем подсчёте.

Диаграммы можно перестроить отдельно, без открытия базы и нового подсчёта:

```powershell
py code/histograms/plot_flight_counts.py
```

Нужна библиотека `matplotlib` (`py -m pip install matplotlib`); в Python проекта
она уже установлена. В длинных отчётах картинки разбиваются на страницы по
25 мест, без отбрасывания остальных. `charts/current_charts.txt` перечисляет
картинки текущего запуска; файлы старых страниц могут оставаться в папке.
Это диаграммы количества рейсов, а не количества пассажиров.

В начале Python-файла настрой `BOTTOM_N = 7`: в каждом из четырёх отчётов
и списков в терминале будут **7 мест с наименьшим числом рейсов**
(или все, если мест меньше 7). Сортировка — по числу рейсов от меньшего
к большему, при равенстве — по названию/коду. `BOTTOM_N = None` выводит все места.
Считаются рейсы за все даты. Диагностический список расхождений остаётся полным.

Для выбранных **городов и аэропортов прибытия** под счётчиком печатаются имена
пассажиров. Детали сохраняются в `destination_passengers.csv`: место, рейс,
дата, имя, источник и способ получения имени. Запрос —
`passengers_by_destination.sql`; он вызывается из основного Python-скрипта.

Имена берутся из ФИО BoardingData, `raw_name` посадочных талонов, `PaxName`
Sirena, имени Pointz. Форум связан с `forum_users` по `profile_id`; при отсутствии
имени используется ник. Для SkyTeam карта сопоставляется с картами Pointz и форума:
имя выводится, только если все найденные непустые имена карты совпадают после
приведения регистра. Неоднозначная или неизвестная карта остаётся без имени.
Такая связь по карте — кандидат на сопоставление, её источник указан в CSV.

Каждый пассажир связан именно с пунктом назначения в его исходной записи;
имя не переносится на другие пункты назначения только из-за совпадения рейса
и даты. Для источников без названия города города не восстанавливаются по IATA.
Повторяющиеся написания имени в списке места показываются один раз, но разные
написания не объединяются в одну личность. Неизвестные имена отмечаются отдельно.

Пустые места, пустые номера рейсов и отсутствующие/непреобразуемые даты
исключаются из подсчёта. Значение вроде `5262` не трактуется как дата Excel.
Разные написания одного города, кроме регистра и пробелов по краям, не объединяются.

Если для одного номера и дня указаны разные места одного типа и направления,
рейс считается **по одному разу в каждом указанном месте**. Такие случаи
выводятся в `location_conflicts.csv`: это могут быть ошибки источников или
разные участки маршрута. Поэтому сумма по местам не обязательно равна числу
уникальных пар «рейс + дата» во всей базе. Подсчёт отражает покрытие источников,
а не все реальные рейсы авиакомпаний.

## Рейсы каждого пользователя

`passenger_flights.sql` выводит имя, дату, номер рейса, город назначения и багаж
из `source."boarding_data + boarding_passes"`. Сначала используются поля
`raw_name`, `raw_date`, `flight_number`, `to_city`; при пропусках — ФИО
из трёх полей, `FlightDate`, `FlightNumber`, `Destination`.
Пустые строки тоже считаются пропусками. Даты преобразуются в `DATE`;
если `raw_date` не удаётся преобразовать, используется `FlightDate`.

Сортировка — по имени, затем по дате от ранних рейсов к поздним.
Неизвестные даты выводятся в конце списка человека. Для одного человека
в запросе есть закомментированное условие `WHERE`.

Имя здесь — подпись для группировки строк при сортировке, а не уникальный
идентификатор человека: однофамильцы могут смешиваться, а разные написания
имени одного человека попадать в разные группы. Дубликаты не удаляются.

## Частые перелёты в один город

`frequent_destinations.py` использует запрос из `passenger_flights.sql`
и считает строки для каждой пары «имя — город». В начале Python-файла
есть настройка `FLIGHT_THRESHOLD = 5`: выводятся только пары с количеством
**строго больше 5**, то есть от 6. Каждый подходящий город выводится отдельно.
Для просмотра всех непустых пар задай порог 0.
Вместо количества в результате выводятся даты рейсов по возрастанию,
рядом с каждой датой — соответствующее значение `Baggage`:
`2018-01-01 (багаж: Registered)`.
Дата и багаж собираются вместе, чтобы сохранить их соответствие.
Отсутствующий багаж (`NULL` или пустая строка) отображается как «нет данных»;
текстовое значение `None` сохраняется как `None`.
Повторяющиеся даты сохраняются, неизвестные выводятся в конце как
«дата неизвестна». Для проверки порога по-прежнему считаются все записи,
включая записи с неизвестной датой.

Запуск из папки проекта (нужна библиотека DuckDB, установка описана ниже):

```powershell
py code/spy_search/frequent_destinations.py
```

Перед запуском останови сервер DuckDB UI командой `закройте приложение, которое держит файл базы`
из корня проекта. Закрытие вкладки браузера не останавливает сервер.
Скрипт открывает базу только для чтения и печатает результат в терминал.
Функцию можно вызвать отдельно: `find_frequent_destinations(connection, 5)`.

Строки без имени или города исключаются. Счётчик считает записи исходного
запроса, включая возможные дубликаты, а не проверенные уникальные перелёты.
Имена и города группируются по их написанию без дополнительного сопоставления.

## Число рейсов между парами городов и аэропортов

```powershell
py code/histograms/count_flight_routes.py
```

`flight_route_counts.sql` считает для каждой направленной пары число уникальных
сочетаний номера рейса и даты. Повторы у пассажиров и между источниками удаляются.
Обратное направление считается отдельной парой. В отчёт выводятся все пары,
сначала с наибольшим числом рейсов, и общее количество разных пар в каждой категории.
Весь отчёт сохраняется в `results/flight_routes.txt` (UTF-8), в консоли остаётся
пути к файлам. При следующем запуске отчёт перезаписывается. База не меняется.

После сохранения отчёта открывается интерактивное окно Matplotlib с двумя
столбчатыми диаграммами: для городов и аэропортов. По X — названия направленных
пар, по Y — число уникальных рейсов. Все пары доступны, независимо от
`SELECTED_PAIR`, и отсортированы по убыванию числа рейсов.
`PAIRS_PER_PAGE = 12` задаёт число пар на странице. Под каждым графиком есть
свой ползунок для выбора страницы; высота шкалы Y подстраивается под страницу.
Q1 (25-й процентиль) и Q3 (75-й процентиль) числа рейсов рассчитываются отдельно
для всех пар городов и всех пар аэропортов, с одинаковым весом каждой пары.
Используется `numpy.quantile` с линейной интерполяцией. Значения записываются
в текстовый отчёт и показаны горизонтальными линиями с легендой на диаграммах.
При переключении страницы квартили не пересчитываются.
Панель окна позволяет масштабировать, перемещать график и сохранять изображение.
Первые страницы автоматически сохраняются в `results/flight_routes_histogram.png`.
`SHOW_WINDOW = False` отключает окно. Перед открытием окна соединение с БД закрывается.

| Категория | Таблица | Отправление → прибытие | Номер + дата |
| --- | --- | --- | --- |
| Города | boarding_passes | from_city → to_city | flight_number + raw_date |
| Города | forum_flights | from_city → to_city | flight_number + flight_date |
| Аэропорты | boarding_passes | from_iata → to_iata | flight_number + raw_date |
| Аэропорты | sirena | From → Dest | Flight + ArrivalDate |
| Аэропорты | forum_flights | from_iata → to_iata | flight_number + flight_date |
| Аэропорты | pointz_activities | origin → destination | flight_number + flight_date |
| Аэропорты | skyteam_exchange | from_iata → to_iata | flight_number + flight_date |

Названия и коды приводятся к верхнему регистру, пробелы по краям удаляются.
В номерах рейсов удаляются обычные пробелы, даты преобразуются в DATE.
Строки без обоих пунктов маршрута, номера или корректной даты исключаются.
Разные написания названий городов дополнительно не сопоставляются.
Если источники указывают разные маршруты для одного номера и даты,
рейс учитывается по одному разу в каждом из этих маршрутов.

В `count_flight_routes.py` можно выбрать пару для подробного просмотра:

```python
ROUTE_TYPE = 'airport'  # Или 'city'
SELECTED_PAIR = ('SVO', 'CDG')  # Для городов, например ('MOSCOW', 'PARIS')
```

После счётчиков функция `show_route_rows(connection, route_type, pair)` выводит
в отчёт все поля исходных строк этой направленной пары, отдельно по таблицам.
Регистр и пробелы по краям не влияют на поиск. Повторы сохраняются;
строки с отсутствующим номером рейса или некорректной датой тоже показываются,
хотя в счётчик уникальных рейсов они не входят. Поэтому число исходных строк
может отличаться от числа рейсов. `SELECTED_PAIR = None` отключает этот вывод.

Для Sirena намеренно используется ArrivalDate. При перелёте через полночь
она может отличаться от даты вылета в других источниках: тогда записи
не объединятся и будут посчитаны отдельно.

### Исходные строки пар с малым числом рейсов

В том же скрипте `FLIGHT_THRESHOLD = 10` задаёт строгий порог: выбираются пары,
у которых **меньше 10** уникальных рейсов (10 уже не входит). `ROUTE_TYPE`
задаёт города или аэропорты; `SELECTED_PAIR` на эту выгрузку не влияет.
Функция `save_routes_below_threshold(connection, counts, route_type, threshold)`
вызывает `show_route_rows` для каждой подходящей пары и сохраняет результат
в `results/rare_route_rows.txt`, начиная с пар с наименьшим числом рейсов.
Выводятся все поля и все исходные повторы. Порог относится к числу уникальных
рейсов пары, а не к числу строк в источниках. Если пар нет, файл содержит
заголовок и нулевое количество. При каждом запуске файл перезаписывается.

## Число перелётов каждого номера рейса

```powershell
py code/histograms/count_flights_by_number.py
```

Новый запрос `flight_number_counts.sql` сначала учитывает уникальные сочетания
номера рейса, даты и времени из `boarding_passes` (`raw_date`, `flight_time`)
и `sirena` (`DepartDate`, `DepartTime`). Одинаковые сочетания, включая повторы
у пассажиров и между таблицами, считаются один раз. Разное время — разные перелёты.

Из `boarding_data` (`FlightDate`), `forum_flights`, `pointz_activities` и
`skyteam_exchange` (`flight_date`) берётся только дата. Она добавляет один перелёт,
только если для этого номера и дня нет записей с известным временем.
Несколько записей без времени в один день не добавляют несколько перелётов.
Пустое или некорректное время также обрабатывается как неизвестное.
Строки без номера или корректной даты исключаются. В номерах игнорируются
регистр и пробельные символы. Время `boarding_data.FlightTime` не используется
согласно выбранной схеме. Часовые пояса и расхождения расписания не исправляются:
разное время одного фактического вылета в источниках может завысить счётчик.

В `results/flights_by_number/` сохраняются `counts.csv`, `counts.txt` и
`histogram.png`. Отчёты содержат общий счётчик `total_flights` и отдельные
счётчики шести таблиц. Общий результат не равен их сумме, поскольку повторы
между источниками удаляются. Для таблиц без времени отдельный счётчик равен
числу уникальных дат номера рейса.

Интерактивный график: X — номер рейса, Y — общий счётчик перелётов.
Q1 (25-й процентиль) и Q2 (медиана, 50-й процентиль) рассчитываются по общим
счётчикам всех номеров рейсов, каждый номер имеет равный вес. Используется
линейная интерполяция `numpy.quantile`. Значения записываются в `counts.txt`
и показаны горизонтальными линиями на графике; от выбранной страницы не зависят.
Сортировка — по убыванию счётчика, при равенстве по номеру рейса.
`FLIGHTS_PER_PAGE = 20` задаёт число номеров на странице; ползунок открывает
остальные. Картинка сохраняет первую страницу. `SHOW_WINDOW = False`
отключает окно. База открывается только для чтения и закрывается до показа окна.

## Перелёты пассажиров с признаком багажа

```powershell
py code/histograms/count_passenger_baggage_flights.py
```

`passenger_baggage_counts.sql` объединяет `boarding_data.PassengerDocument`
с `sirena.TravelDoc`. Для каждого документа считается число уникальных билетов
(`TicketNumber` / `e-Ticket`) с признаком багажа:

- `boarding_data.Baggage`: Registered, Transit, Delayed;
- `sirena.Baggage`: 1PC, 2PC.

Достаточно положительного признака в одном источнике. При расхождении с None
или 0PC в другом источнике билет всё равно учитывается один раз. Повторы одного
билета у того же документа не увеличивают счётчик. None, 0PC, пустые и неизвестные
значения сами по себе не дают положительного признака. В Sirena 1PC и 2PC — это
багажная норма, поэтому показатель не доказывает фактическую сдачу багажа.

Пустые документы и маркеры отсутствия исключаются; документы и билеты остаются
строками, пробельные символы удаляются, регистр нормализуется. Билеты с маркерами
отсутствия не считаются. Все документы с корректным номером остаются в выборке,
включая документы со счётчиком 0. Ноль означает отсутствие известного билета
с выбранным признаком, а не доказанное отсутствие багажа во всех поездках.

X — число таких билетов у пассажира, Y — количество пассажиров (документов).
Q1 и Q3 вычисляются по счётчикам всех документов, включая нули, с одинаковым
весом каждого документа (`numpy.quantile`, линейная интерполяция).
В `results/passenger_baggage_counts/` сохраняются `passengers.csv` с ФИО,
`distribution.csv`, `statistics.json` и `histogram.png`. Интерактивное окно
открывается после закрытия соединения с базой; `SHOW_WINDOW = False` отключает его.

## Багаж

`baggage_mismatches.sql` сопоставляет записи по трём полям одновременно:

| boarding_data | sirena |
| --- | --- |
| PassengerDocument | TravelDoc |
| FlightNumber | Flight |
| FlightDate | DepartDate |

В документе игнорируются обычные пробелы, в номере рейса — регистр букв
и пробелы по краям. Даты приводятся к типу `DATE` через `TRY_CAST`.
Пустые и NULL-документы и номера рейсов, а также отсутствующие или
непреобразуемые даты не соединяются.

Ищем две комбинации:

| boarding_data.Baggage | sirena.Baggage |
| --- | --- |
| Registered, Transit или Delayed | 0PC или None |
| None | 1PC или 2PC |

В текущей Sirena есть `0PC`, а текстового `None` нет. На случай его появления
в запрос включены оба значения. Пустая строка и SQL NULL — неизвестные значения,
они не считаются отсутствием багажа.

Сравниваются записи одного документа на один номер рейса в один день.
Даты, рейсы и номера исходных строк включены в результат для проверки.
Если в источниках есть несколько записей с одинаковыми тремя ключами,
запрос вернёт все подходящие пары этих записей.

`0PC` означает отсутствие включённых мест сдаваемого багажа, а не гарантированное
отсутствие фактического багажа. Поэтому результат — кандидаты для проверки
по выбранному правилу, а не доказательство обмана или шпионажа.

## Запуск в открытом DuckDB UI

Скопируй содержимое `baggage_mismatches.sql` в SQL-ячейку и нажми ▶.
В ячейке выбери базу `catch_the_spies`. Запрос только читает данные.

## Запуск из Python

Установи библиотеку один раз:

```powershell
py -m pip install duckdb==1.5.6
```

Перед отдельным запуском Python останови сервер DuckDB UI, который держит базу
открытой на запись. Закрытие одной вкладки браузера не останавливает сервер.

Из папки проекта:

```powershell
py code/spy_search/baggage_mismatches.py
```

Функция `find_baggage_mismatches(connection)` возвращает результат запроса.
При запуске скрипта показывается до 20 строк; сам SQL не ограничивает результат.
Для получения всех строк в Python используй `result.fetchall()`.
