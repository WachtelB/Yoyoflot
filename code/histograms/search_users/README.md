# Пассажиры по значению X гистограммы

## Пересечения выборок

`find_user_intersections.py` находит пассажиров, попавших в несколько мини-скриптов.
Он использует **текущие X из самих find_*.py**, заново рассчитывает выборки и
сравнивает документы. Старые TXT не читаются и не перезаписываются.
Поэтому менять X и запускать все большие выгрузки перед поиском пересечений не нужно.

В начале `find_user_intersections.py`:

```python
MIN_MATCHES = 2     # Хотя бы в двух разных скриптах.
# MIN_MATCHES = 3   # Хотя бы в трёх.
# MIN_MATCHES = None  # Во всех скриптах из SEARCH_MODULES одновременно.
```

В `SEARCH_MODULES` можно оставить только интересующие скрипты. В текущем
варианте из пересечения исключены `find_airlines` и
`find_min_flight_interval`; остальные семь пассажирских метрик включены.
Две выборки `find_max_flights` (7/30 дней) объединяются: достаточно попадания
в любую из них, а при попадании в обе это всё равно один совпавший скрипт.
Пустая выборка учитывается: пересечение всех скриптов с ней пусто.

```powershell
.\.venv\Scripts\python.exe -X utf8 code/histograms/search_users/find_user_intersections.py
```

Результат: `<project>\code\histograms\results\user_search\user_intersections_outliers.txt`.
В нём условия X, размеры выборок, число общих документов для каждой пары скриптов
и список пассажиров: документ, ФИО, число совпавших скриптов и значения показателей.
Сначала идут пассажиры с наибольшим числом совпадений. Исходные строки повторно
не выгружаются; они остаются в индивидуальных отчётах поиска.

## Индивидуальные выборки

Каждый `find_*.py` находит документы с выбранным значением показателя и сохраняет
отдельный TXT в `<project>\code\histograms\results\user_search`.
В файле: документ, ФИО, значение X, детали расчёта (если есть) и все поля исходных строк.
Пользователь определяется по документу; одинаковые имена не объединяются.

## Настройка

В начале нужного мини-скрипта измените глобальную переменную:

```python
SELECTED_X = 3        # Только пассажиры с X = 3.
SELECTED_X = [0, 1]   # Пассажиры с X = 0 или X = 1.
SELECTED_X = None     # Автоматически выбрать минимальное известное X.
```

Для текущего анализа используются верхние границы выбросов:

```text
IQR = Q3 - Q1
верхняя граница = Q3 + 1,5 × IQR
условие выбора = X > верхняя граница
```

Для целочисленной метрики условие автоматически соответствует ближайшему целому
значению выше границы. Например, `X > 3,5` означает `X >= 4`. Пропуски
показателя не участвуют в выборе.

| Гистограмма | Мини-скрипт | Текущая граница выброса |
| --- | --- | --- |
| `count_unique_routes.py` | `find_unique_routes.py` | `X > 3,5` |
| `count_max_flights.py` | `find_max_flights.py` | `X > 1` для 7 дней; `X > 3,5` для 30 дней |
| `count_min_flight_interval.py` | `find_min_flight_interval.py` | 428 часов (Q3 = 427,5; не входит в пересечение) |
| `count_route_repetitions.py` | `find_route_repetitions.py` | `X > 1` |
| `count_quick_returns.py` | `find_quick_returns.py` | `X > 0` |
| `count_airlines.py` | `find_airlines.py` | исключена из пересечения |
| `count_loyalty_cards.py` | `find_loyalty_cards.py` | `X > 2,5` |
| `count_passenger_flights.py` | `find_passenger_flights.py` | `X > 6` |
| `count_passenger_baggage_flights.py` | `find_passenger_baggage_flights.py` | `X > 2,5` |

В `find_max_flights.py` настройки отдельные: `SELECTED_X_7_DAYS` и
`SELECTED_X_30_DAYS`. Один TXT содержит два раздела.

В `find_min_flight_interval.py` есть `X_RANGE = None`. Для диапазона часов задайте,
например, `X_RANGE = (0, 24)`: выбирается `0 <= X < 24`, независимо от `SELECTED_X`.
Это полезно для широких столбцов гистограммы непрерывной величины.
Верните `X_RANGE = None` для поиска точного X.

## Запуск

Из PowerShell в `<project>`:

```powershell
.\.venv\Scripts\python.exe -X utf8 code/histograms/search_users/run_all_user_searches.py
```

Или двойной щелчок по `<project>\run_user_search.cmd`.
Общий запуск читает настройки из каждого мини-скрипта, повторно использует данные
между расчётами и создаёт девять TXT. Графики при этом не открываются.

Один поиск:

```powershell
.\.venv\Scripts\python.exe -X utf8 code/histograms/search_users/find_passenger_flights.py
```

TXT называется так же, как мини-скрипт: например,
`<project>\code\histograms\results\user_search\find_passenger_flights.txt`.
Повторный запуск заменяет соответствующий отчёт, в том числе при пустом результате.
Если Windows не разрешает заменить TXT (например, он занят другой программой),
результат сохраняется рядом с датой и временем в имени. Фактический путь выводится
в консоль и попадает в `last_run.json`; старый занятый отчёт остаётся прежним.
`last_run.json` содержит количество документов и исходных строк последнего запуска.
Пути определяются через `pathlib`, поэтому запуск из PyCharm не зависит от рабочей папки.
Если база занята просмотрщиком, запустите `<project>\закройте приложение, которое держит файл базы`.

## Что находится в отчёте

Расчёт выполняется по текущей базе теми же функциями и SQL, что и график.
Если данные или настройки графиков изменились, для сравнения пересчитайте и график.
Каждая исходная запись записана одной JSON-строкой с названиями всех полей;
исходные дубли сохранены. Ограничения на число пассажиров или строк нет,
поэтому некоторые отчёты могут быть большими.

- Для семи новых метрик перелётов: строки `boarding_data`, `sirena` и
  `boarding_passes`, однозначно связанные через билет с выбранным документом.
- Для числа билетов и билетов с багажом: `boarding_data` и `sirena`.
- Для карт: `boarding_data`, `sirena`, а также `forum_loyalty` и
  `pointz_activities` по принятым связям карт и профилей.

Исходные строки дают контекст пассажира: не каждая из них добавляет единицу
к показателю. При расчёте удаляются повторы, учитываются окна времени и пропуски.
Для метрик с подробностями отдельно выводятся данные расчёта, например пара
вылетов с минимальным промежутком или самое активное окно.
Карты лояльности не расширяют список перелётов в текущих гистограммах.

В метрике багажа `1PC`/`2PC` означают включённую норму; наличие фактически сданного
багажа из этих кодов не следует. В метрике авиакомпаний учитываются коды только
из рейсов, привязанных к документу в текущем расчёте.
