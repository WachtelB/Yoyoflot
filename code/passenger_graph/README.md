# Граф совместных вылетов пассажиров — Sigma.js

Запуск из корня проекта двойным щелчком: **`<project>\open_graph.cmd`**.
Он пересчитывает граф и открывает локальную страницу в браузере.
Исходная база открывается только для чтения и закрывается до открытия страницы.
Окно запуска нужно оставить работающим: закрытие вкладки не останавливает сервер.
Для остановки нажмите Ctrl+C в окне запуска.

Готовая галерея для отчёта запускается двойным щелчком по
**`<project>\open_graph.cmd`**. В ней находятся две версии:

- минимум один общий вылет — обзор всех связанных пассажиров;
- минимум два общих вылета — только повторные встречи тех же пар.

PNG-файлы лежат в `results/graph_gallery`. Чтобы пересоздать их после обновления
графа, запустите `export_graph_images.py`.

## Команды

```powershell
# Пересчитать и открыть граф:
.\.venv\Scripts\python.exe -X utf8 code/passenger_graph/build_passenger_graph.py

# Только пересчитать, без браузера:
.\.venv\Scripts\python.exe -X utf8 code/passenger_graph/build_passenger_graph.py --no-open

# Открыть уже построенный граф, без повторного расчёта:
.\.venv\Scripts\python.exe -X utf8 code/passenger_graph/serve_graph.py
```

Для запуска из PyCharm подходит `build_passenger_graph.py`, интерпретатор
`<project>\.venv\Scripts\python.exe`. Переменная `OPEN_VIEWER = False` отключает
автоматический запуск страницы. Порт выбирается свободный; адрес `127.0.0.1`
выводится в консоль. Ссылка действительна, пока работает этот запуск.

## Какие связи строятся

1. Узел — нормализованный `PassengerDocument` / `TravelDoc`. Пробелы убираются,
   ведущие нули сохраняются. ФИО — подпись, одинаковые имена не объединяются.
2. Используются `boarding_data`, `sirena` и `boarding_passes`. Посадочный талон
   привязывается по `e_ticket` к `TicketNumber` / `e-Ticket`, только если билет
   соответствует одному документу.
3. Конкретный вылет определяется пятью полями:
   **номер рейса + дата вылета + время вылета + аэропорт отправления + аэропорт прибытия**.
4. Маршрут дополняется из связанной записи только при однозначности.
   События без времени или однозначного маршрута не образуют связи.
   Несколько разных времён одного документа/рейса/даты консервативно считаются
   противоречием: эта группа исключается. Это может пропустить реальные повторные
   вылеты за день; правило выбрано, чтобы не создавать ложные совпадения.
5. Пары строятся внутри каждого вылета. Не перебираются все пары 101 тысячи пассажиров.
   Условие `A < B` исключает петли и зеркальные дубли; повторные исходные записи
   не увеличивают вес связи.
6. Вес ребра — число разных общих вылетов. Для ребра сохраняются все эти вылеты.

Все документы из первых двух источников остаются узлами, даже если связей нет.
Это не все профили всех источников: пользователи форумов и другие записи без
надёжной связи с документом в этот граф не добавляются.
Разные документы одного физического человека пока считаются разными узлами.
Кодшеринговые номера не объединяются. Совпадение записей не доказывает посадку
в самолёт или знакомство пассажиров.

## Просмотр

- По умолчанию рисуются все связи и только связанные узлы. 21 тысяча документов
  без связей не образует серый круг в общем виде, но остаётся в данных и поиске.
- Поиск по документу работает и с пробелами; можно искать часть имени.
- Нажатие на пассажира показывает его прямых попутчиков и список справа.
  Это отдельный вид: связи между самими попутчиками в нём не рисуются.
- Нажатие на линию или кнопку «Общие вылеты» показывает рейсы, даты, время и маршрут.
- Минимум совместных вылетов и даты применяются кнопкой «Применить фильтры».
  Границы дат включены. Вес связи пересчитывается **внутри выбранного периода**.
- «Скрыть без видимых связей» убирает узлы без связей после применения фильтров.
  Найти такой документ через поиск всё равно можно.
- «Показать весь граф» возвращает общий вид, сохраняя установленные фильтры.
  Чтобы вернуть исходное состояние, задайте минимум 1, очистите даты и оставьте
  флажок скрытия изолированных узлов включённым, затем примените фильтры.
- Во время перемещения линии временно скрываются для скорости. Подписи в общем
  виде изначально отключены, в окружении пассажира включены автоматически.

Цвета обозначают группы Louvain по плотности взвешенных связей, а не категории
подозрительности. Группы вычисляются на полном графе и при фильтрации не пересчитываются.
Начальные координаты размещают каждую группу прямоугольной сеткой в отдельной области;
круговая раскладка не используется, чтобы плотные группы не выглядели большими узлами.
Расстояния между областями
не являются географическими или временными. Для небольшого окружения пассажира
применяется ForceAtlas2.

## Файлы и повторяемость

- `prepare_graph.sql` — узлы, вылеты, принадлежность пассажиров вылетам и пары.
  Использует общий `code/histograms/prepare_passenger_metrics.sql`.
- `build_passenger_graph.py` — расчёт и экспорт.
- `layout.cjs` / `layout_bundle.cjs` — группы и координаты; фиксированный seed 42.
- `viewer.js`, `web/index.html`, `web/style.css` — исходники интерфейса.
- `web/app.js` — готовая локальная сборка Sigma.js.
- `results/passenger_graph/graph.json.gz` — полный граф с деталями вылетов.
- `results/passenger_graph/summary.json` — размеры графа и исключения.
- `results/passenger_graph/viewer.json` — адрес последнего запуска просмотрщика.

Схема компактного JSON:

```text
nodes[i] = [документ, ФИО, x, y, группа, число соседей]
flights[i] = [номер рейса, дата, время, откуда, куда, число документов]
edges[i] = [индекс узла A, индекс узла B, индексы общих вылетов]
```

Node.js используется для размещения графа. Скрипт ищет `node` в PATH, затем
в подготовленном окружении Codex на этом компьютере. Пакеты Python уже входят
в окружение проекта. JavaScript-библиотеки включены в локальные сборки;
при обычном запуске скачивание из интернета не требуется, данные остаются на компьютере.

При изменении `viewer.js` или `layout.cjs` пересоберите файлы (нужны Node.js и pnpm):

```powershell
cd graphs
pnpm install --frozen-lockfile
node bundle.cjs
```

Версии закреплены: Sigma.js 3.0.2, Graphology 0.26.0, Louvain 2.0.2,
ForceAtlas2 0.10.1, esbuild 0.25.0. `pnpm-lock.yaml` фиксирует зависимости.
После сборки обновите страницу; после изменения алгоритма повторите расчёт.
